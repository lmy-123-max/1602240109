# 牙科门店管理系统（生产实用版）

《系统分析与设计》课程项目 —— 规约驱动开发（SBD）实现，在课程演示版基础上升级为**可长期实际使用**的门店管理系统。

对应设计文档：《牙科门店管理系统设计与实现》（交付物目录），数据库设计与论文 4.6 节一致（24 张表）。

## 这一版和"课程演示版"的区别

| 能力 | 演示版 | 本版（实用版） |
|---|---|---|
| 数据存储 | 内存库，重启清零 | **文件库 `data/dental.mv.db`，重启/升级不丢数据** |
| 数据安全 | 无 | **每天 02:30 自动备份 + 启动补备份 + 手动备份/下载/恢复** |
| 数据流转 | 手工录入 | **CSV 导出（患者/预约/账单），Excel 双击可开，财务对账/迁移可用** |
| 大数据量 | 全量渲染 | **患者/预约/账单列表分页（20 条/页）+ 关键字搜索 + 日期区间筛选** |
| 运维痕迹 | 无 | 运行日志写入 `logs/dental.log` |
| 演示数据 | 每天强制生成 | 可开关（`app.demo-appointments`），正式使用关闭即可 |

## 快速开始

### 方式一：IntelliJ IDEA 打开运行（推荐，本项目已配好 IDEA 工程）

1. 打开 IDEA → `File → Open` → 选择 **`dental-clinic-system` 文件夹**（即含 `pom.xml` 的这一层）→ 以 Project 方式打开。
2. 首次打开 IDEA 会识别到 Maven 项目自动导入，右下角进度条等待依赖索引完成（依赖已有本地缓存，一般无需联网下载）。
   - 若提示 **"No SDK" / "Project JDK is not defined"**：点击右下角提示或 `File → Project Structure → SDK`，选择本机已安装的 **JDK 17**（没有可点 `Download JDK` 直接下载一个 17）。
3. 导入完成后，右上角运行配置下拉框会出现现成的 **「牙科门诊系统 (Spring Boot)」** 配置（主类 `DentalClinicApplication`，激活 `h2` 配置，工作目录即项目根目录，数据库落到 `./data`），点绿色三角 ▶ 直接运行。
4. 控制台出现 `Started DentalClinicApplication` 后访问 http://localhost:8080/index.html 。
5. 改代码后：点 ▶ 旁边的 🔄（Rerun）重启即可；如需打包成 jar，用右侧 Maven 面板 `Lifecycle → package`。

> 注意：**必须用上面步骤打开 `dental-clinic-system` 这一层文件夹**，而不是它的上层「网页」文件夹，否则 Maven 项目与运行配置不会被识别。

## 数据保存在哪里

- **数据库文件**：`data/dental.mv.db`（首次启动自动建表 + 基础数据；之后重启一律跳过初始化）
- **备份文件**：`backup/dental-YYYYMMDD-HHmmss.zip`（每天 02:30 自动备份；启动时超过 20 小时未备份会自动补一份；只保留最近 30 份）
- **运行日志**：`logs/dental.log`
- **恢复**：管理后台「数据备份」页 → 选备份点「恢复」→ **关闭系统重新启动**即生效（当前库会自动留档为 `data/dental-before-restore-时间.mv.db`）
- **重置**：想回到初始状态，停止系统后删除 `data` 目录即可

## 数据导出

管理后台「数据导出」页：患者档案 / 预约记录 / 收费单据，支持按日期范围导出，CSV 带 UTF-8 BOM，Excel/WPS 直接打开无乱码。

## 正式投入使用前的建议

1. **关闭演示预约**：`application.yml` 中 `app.demo-appointments` 改为 `false`（否则每天自动生成演示病人）。
2. **修改默认密码**：用 admin.html「账号管理」的"重置密码"或首次登录后修改各账号密码。
3. **异地备份**：每周从「数据备份」页下载一份 zip 存到网盘/U 盘。
4. **大型门诊/多终端**：默认 H2 文件库适合单机 1~10 台电脑共用（通过局域网访问 `http://<本机IP>:8080`）。规模更大或需要异地部署时切换 MySQL：

```
# 1) 安装 MySQL 8，执行 src/main/resources/sql/schema-h2.sql 建库（H2/MySQL 兼容语法）
# 2) 修改 application.yml 中 mysql 段的账号密码
# 3) 启动：java -jar target/dental-clinic-system-1.0.0.jar --spring.profiles.active=mysql
```

## 核心业务规则（与设计文档一致）

1. **预约挂号**：预付挂号费 20 元；号源容量不超过门店可用牙椅数；法定节假日不可预约。
2. **取消与违约**：距就诊 >2 小时取消免费退挂号费；≤2 小时收 50% 违约金。
3. **爽约处理**：已确认超时未签到自动关闭（状态 6），号源二次投放。
4. **过敏史强制校验**：处置项目命中过敏原时拦截提交并留痕。
5. **电子账单**：病历提交后自动生成，金额不可改；挂号费抵扣诊疗费；退款红冲。
6. **医保核算**：价目库标注医保属性（甲类全额 / 乙类 70% / 自费），账单自动拆分「医保统筹报销」与「个人自付」，恒等式：实收 = 医保报销 + 自付；支持医保结算支付渠道。
7. **业绩核算**：净利润 = 经办收入 − 直接耗材成本 − 分摊运营成本；激励奖金 = 净利润 × 10%。
8. **排班约束**：同一医生不可同时在两家门店出诊；同一牙椅同时段不可分配给两位医生。
9. **多医生协同**：门店共享候诊队列，任意医生可接诊其他医生名下候诊患者，接诊自动改派。

## 政策合规与操作留痕改版（2026-11 第五次）

### 国家政策合规
- **《个人信息保护法》**：注册需勾选《个人信息处理告知书》同意栏；患者/牙医可自助注销账户，注销后姓名、手机、证件、过敏史等个人信息**匿名化清除**（姓名改写为「已注销患者#ID」），符合最小必要原则。
- **《医疗机构病历管理规定》**：病历与账单依法须留存——注销后保留匿名档案（健康卡号），但与本人身份完全解绑。
- **《医疗保障基金使用监督管理条例》**：医保结算按甲/乙类口径自动核算并留痕，退款时注明「医保报销部分按原渠道退回统筹基金」；官网公示医保定点与明码标价。
- **实名制与审计**：登录留痕 + 操作留痕双轨，所有关键业务动作可追溯到「谁、何时、对什么、做了什么」。

### 账户注销（患者/牙医自助）
